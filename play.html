📌 왜 이 파일이 오늘 만드는 파일 중 가장 중요한가

클로드는 세션이 끝나면 대화를 전부 잊습니다. 딱 하나, 매 세션 시작 때 자동으로 다시 읽는 파일이 CLAUDE.md — 채팅에 친 지시는 오늘만 유효하지만, 이 파일에 쓴 지시는 영구 유효합니다. 같은 모델을 써도 결과가 다른 이유가 이 파일의 품질입니다.

잘 쓰는 법 5가지:

  1. 짧고 명령형으로 — “~해라 / ~하지 마라”. 길어질수록 희석됩니다
  2. 반복 지시는 전부 이관 — 같은 말 두 번 쳤다면 그 즉시 CLAUDE.md행 (오늘의 승격 공식)
  3. 금지사항을 먼저 — “하지 마라”가 “해라”보다 강력 (예: 과장 표현 금지)
  4. 자주 쓰는 명령·폴더 구조 기록 — 클로드가 헤매지 않게
  5. 대화하며 키우기 — “방금 그 규칙 CLAUDE.md에 추가해줘” 한 줄이면 끝

💡 개인 취향(존댓말·언어)은 홈의 ~/.claude/CLAUDE.md에, 프로젝트 규칙은 프로젝트 폴더의 CLAUDE.md에 — 클로드는 둘 다 읽습니다.

Shift+Tab을 누를 때마다 모드가 순환합니다 (현재 모드는 입력창 아래에 표시됩니다):

왜 «먼저» 깔아야 하나 — 3가지 이유

  1. 결과 품질이 시작부터 달라집니다 — 같은 프롬프트라도 «작업 순서를 강제하는 규칙»이 깔려 있으면 결과가 다릅니다. 나중에 깔면 오늘 만든 걸 다시 만들어야 해요.
  2. 내가 몰라도 프로의 순서로 일합니다 — 계획 → 검증 → 구현 → 회고. 숙련자가 지키는 순서를 플러그인이 대신 강제합니다.
  3. 직접 만들 필요가 없습니다 — 전 세계가 검증한 부품이 무료로 공개돼 있습니다. 오늘 할 일은 «만들기»가 아니라 «고르고 조립하기».

4-1. git init — 폴더를 「저장소」로 만들기 · 📽 PPT: M2 「가장 먼저」 (12:05)

커밋·푸시보다 이게 먼저입니다. init을 안 한 폴더에서 커밋하면 fatal: not a git repository 에러가 납니다.

터미널에서 (프로젝트 폴더당 딱 한 번만):

bash
cd my-fortune        # 내 프로젝트 폴더로 이동
git init             # 이 폴더를 깃 저장소로 만들기
ls -la               # 숨김 파일까지 전부 보기

→ 목록에 .git 디렉토리가 보이면 성공입니다.

💡 .git 폴더가 뭔가요 — 깃이 「이력을 적어두는 장부」입니다. 이 폴더가 생기는 순간부터 모든 변경 기록이 자동으로 쌓입니다. 이게 없으면 커밋 자체가 불가능해요. (직접 열어 수정하지 말 것)

막힐 때:

  • .git이 안 보여요 → 폴더 위치가 다릅니다. pwd로 지금 위치 확인 → 맞는 폴더에서 git init 다시
  • Windows에서 ls -la가 안 돼요 → PowerShell은 ls -Force
  • 처음부터 완전히 다시 하고 싶어요 → rm -rf .git 후 git init (Windows: Remove-Item -Recurse -Force .git)
bash
rm -rf .git
git init
ls -la

⚠ rm -rf .git은 지금까지의 커밋 이력이 전부 사라집니다. 새 프로젝트로 리셋할 때만 쓰세요.

🖱 터미널이 부담되면 — VS Code 왼쪽 [소스 제어] 아이콘(Ctrl+Shift+G) → 「리포지토리 초기화」 버튼 한 번 = git init과 똑같습니다. 누른 뒤 터미널에서 ls -la 하면 .git이 생긴 걸 확인할 수 있어요.

4-2. 스테이징 — 「이번 세이브에 무엇을 담을까」 · 📽 PPT: M2 「스테이징」 (12:06)

커밋을 하려면 먼저 스테이징 영역에 올려야 합니다. 오늘 파일 5개를 고쳤는데 그중 3개만 완성됐다면 — 그 3개만 담아 커밋하고 나머지는 계속 작업하면 됩니다. 커밋은 「저장」이 아니라 「내가 고른 것들의 스냅샷」이에요.

파일의 세 가지 상태 : ① 수정됨(아직 안 담김) → ② 담김(스테이징 완료) → ③ 커밋됨(세이브 확정)

bash
git status                      # 지금 무엇이 담겼고 안 담겼는지 — 막히면 무조건 이것부터
bash
git add index.html              # 이 파일만 골라 담기 (파일명 여러 개 나열 가능)
bash
git add .                       # 폴더 안 전부 담기 — 오늘 실습은 대부분 이것
bash
git restore --staged index.html # 담았던 걸 다시 내려놓기 (작업 내용은 그대로)

🖱 VS Code에서는 클릭으로 — [소스 제어] 탭에서 파일 옆 「＋」가 담기, 「−」가 내리기.

🙈 애초에 담기면 안 되는 것(node_modules · .env 비밀키)은 .gitignore에 적어두면 목록에 아예 뜨지 않습니다.

9★. SOP 매뉴얼 상세 — SKILL.md 해부 · 📽 PPT: M6 「SOP 해부·폴더·품질」 (15:54–16:00)

스킬은 «코딩»이 아니라 신입에게 넘기는 업무 인수인계서입니다. 사람에게 설명하듯 쓰면 그게 곧 좋은 스킬.

SKILL.md 뼈대 — 이 다섯 칸이 전부입니다 (내 상황으로 바꿔 쓰세요):

javascript
---
name: 견적서-작성기
description: 고객사·항목·단가를 주면 부가세까지 계산된 견적서를 만든다. “견적서 만들어줘”에 발동.
---

## 언제 쓰나
- 고객이 견적을 요청했을 때

## 입력받을 것
- 고객사명 / 항목·수량·단가 / 유효기간
- 없으면 지어내지 말고 되물을 것

## 작업 순서
1) 항목 표 생성 2) 소계 3) 부가세 10% 4) 총합
5) 계좌·유효기간 삽입 6) PDF로 저장

## 출력 형식
- A4 1장 · 회사 로고 자리 비워둘 것

## 하지 말 것
- 금액 임의 할인 · 근거 없는 항목 추가

다섯 칸이 하는 일:

  1. 이름·설명 — 언제 발동할지 결정하는 «검색어». 여기가 부실하면 아예 안 불려나옵니다
  2. 언제 쓰나 — 상황을 적어야 클로드가 스스로 판단합니다
  3. 입력받을 것 — «없으면 되물어라»가 핵심 (지어내기 방지 장치)
  4. 작업 순서 — 번호를 매기세요. 순서가 곧 품질입니다
  5. 하지 말 것 — 금지가 지시보다 강합니다. 사고를 여기서 막습니다

스킬은 «폴더» 하나 — 그대로 배포됩니다:

javascript
내-견적서-스킬/
├── SKILL.md          ← 필수. 이것만 있어도 동작
├── REFERENCE.md      ← 길어지는 내용은 분리
├── templates/
│     └── 견적서_양식.md
└── scripts/
      └── calc.py      ← 계산이 복잡하면 스크립트로
  • 폴더째 압축(zip)하면 그대로 «배포 가능한 제품»이 됩니다 · 동료에게 주면 그 사람 클로드에서도 똑같이 동작
  • SKILL.md가 길어지면 REFERENCE.md로 쪼개세요 — 필요할 때만 읽습니다
  • 반복 계산·변환은 스크립트로 빼면 결과가 흔들리지 않습니다

🌐 웹 클로드(GUI)에서도 쓰는 법 — 터미널 없이: claude.ai → 설정(Customize) → Skills → 폴더를 zip으로 압축해 업로드 → 켜기. 무료 플랜에서도 됩니다. ※ 단, 「설정 → 기능」에서 «코드 실행 및 파일 생성»이 켜져 있어야 합니다. → 오늘 CLI에서 만든 스킬을 내일 웹에서도 씁니다.

안 불려나오는 스킬의 3가지 원인 (나쁜 예 → 좋은 예)

  1. ✕ 설명이 추상적 — “description: 문서를 잘 만든다” → ⭕ “description: 고객사·항목·단가를 주면 부가세 계산된 견적서 PDF를 만든다. ‘견적서 만들어줘’에 발동”
  2. ✕ 트리거 문장이 없다 — 언제 쓰는지 안 적음 → ⭕ “견적서/견적/단가표 요청이 오면 이 스킬을 쓴다”를 본문에 명시
  3. ✕ 할 일이 뭉뚱그려져 있다 — “잘 정리해서 만들어라” → ⭕ 1) 표 2) 소계 3) 부가세 4) 총합 5) 저장 — 번호로 쪼갤 것

  • ⭕ 이 셋 중 하나면 스킬감: ① 한 달에 두 번 이상 하는 일 ② 매번 같은 설명을 반복하는 일 ③ 사람이 바뀌면 품질이 흔들리는 일
  • ❌ 반대로 만들지 말 것: 한 번만 할 일 · 매번 조건이 완전히 달라지는 일 · 규칙을 아직 나도 모르는 일(먼저 손으로 3번 해보고)
